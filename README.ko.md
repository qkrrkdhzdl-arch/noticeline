# NoticeLine — 공고문 한 장을 오늘의 할 일로

[English (README.md)](./README.md)

한국어 지원사업 공고문을 붙여넣으면 네 가지를 한 화면에 정리합니다.

1. **자격 대조**: 공고가 요구하는 것(학생 신분, 지역, 사업자등록, 팀 인원)을 읽는 사람의 상황과 비교합니다.
2. **한눈에**: 마감, 지원 규모, 접수 방법, 심사 기준과 각 값의 근거 문장.
3. **제출서류**: 진행률이 붙은 체크리스트.
4. **D-day 계획**: 마감에서 거꾸로 세운 계획과 `.ics` 캘린더 파일.

전부 브라우저 안에서 돕니다. 정적 사이트이고 서버도, 계정도, 추적도 없습니다. 화면은 한국어와 영어를 지원하고, 브라우저 언어로 열리며 헤더의 KR/EN 전환으로 바꿀 수 있습니다. 공고문 자체는 원문 그대로 한국어로 표시합니다.

앱: **https://qkrrkdhzdl-arch.github.io/noticeline/**

## 왜 만들었나

1인 사업자는 해마다 수십 건의 공고에 지원합니다. 문제는 공고문 자체가 아니라, 자격과 서류와 마감이 서로 다른 세 문단에 흩어져 있다는 점입니다. 그걸 읽는 사람은 대개 가게 문을 닫은 밤 11시입니다. 잘못 읽었을 때의 비용은 나쁜 점수가 아니라, 헛되이 뗀 주민등록등본, 놓친 18시 마감, 내 상황과 반대되는 내용에 서명한 참가서약서입니다.

NoticeLine은 한 가지 일만 합니다. 공고문이 자기 조건을 드러내게 하고, 그 근거를 화면에 남겨 둡니다.

## 동작 방식

```
공고문 텍스트 ─▶ 문장 분리 ─▶ 라벨 추출 ─▶ 규칙 엔진 ─▶ 판정 + 계획
                                    │
                                    └── 모든 항목에 근거 문장 보관
```

* **추출**(`engine.js` → `parse`): `마감`·`접수` 근처의 날짜, 단위가 붙은 금액, 주최 줄, 참가대상 문단, 제출서류 문단, 심사 문단을 찾습니다. 기간 표기는 양끝을 함께 읽고, 끝 날짜에 연도가 없으면 앞 날짜의 연도를 이어받습니다. `2026. 11. 13. ~ 12. 10.`의 마감은 12. 10.이고, `2026.12.20~01.05`의 마감은 2027-01-05입니다.
* **규칙 엔진**(`verdict`): 여섯 가지를 봅니다. 학생 신분, 지역(충청권 = 대전·세종·충북·충남 같은 권역 매핑 포함), 사업자등록, 업력, 팀 인원, 마감 여유. 각 판정은 `충족` / `확인 필요` / `불가`와 **그 판단에 쓴 문장**을 함께 돌려줍니다.
* **거꾸로 세운 계획**(`plan`): D-14부터 D-DAY까지, 이미 지난 단계는 건너뜁니다.
* **유사도**(`similar`): 캐시한 공고 묶음에 대한 TF-IDF 코사인 유사도를 브라우저에서 계산합니다.
* **만들어 내지 않습니다.** 공고에 금액이나 마감이 없으면 카드를 비워 두고 `확인 필요`로 남깁니다. NoticeLine은 대신 신청하지 않습니다.

## AI에 대해

기본 구성은 언어 모델이 아니라 결정적인 규칙 엔진입니다. 의도한 선택입니다. 자기 근거 문장을 보여 주지 못하는 모델이 내린 자격 판정은 아무 답도 주지 않는 것보다 나쁩니다.

공고 요약을 위한 **직접 키 입력** 칸을 따로 두었습니다. 기본값은 꺼짐이고, 키를 넣으면 그 페이지의 메모리에만 남으며 공고문은 사용자가 고른 주소로만 전송됩니다. 아무것도 저장하지 않습니다.

## 파일

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 뼈대 |
| `style.css` | 디자인 시스템(프레임워크 없음) |
| `engine.js` | 추출, 규칙, 계획, ICS, 유사도 |
| `app.js` | 화면 렌더링과 상호작용 |
| `i18n.js` | 한국어·영어 문구, 언어 감지, KR/EN 전환 |
| `data/notices.js` | 예시이자 유사도 묶음으로 쓰는 2026년 실제 공고 9건 |
| `test/engine.test.js` | 추출·규칙 테스트(의존성 없음) |

## 실행

`index.html`을 열거나:

```bash
python3 -m http.server 8000
# http://localhost:8000
```

빌드 단계도, 의존성도 없습니다.

## 테스트

```bash
node test/engine.test.js
```

예시 공고 9건을 각 공고가 실제로 가진 마감과 대조하고, 파서가 틀리면 안 되는 날짜 사례를 확인합니다. 끝 날짜에 연도가 없는 기간 표기, 해를 넘기는 기간, 마감이 아닌 본문·일정 날짜, 그리고 같은 결과가 한/영 판정과 계획에 그대로 도달하는지를 봅니다.

## 데이터

예시 공고는 농림축산식품부·한국농어촌공사, 국토교통부·스마트도시협회, 충청남도, 한국사회보장정보원, 한남대학교, 창업진흥원·현대건설, POSTECH, 국민대 차세대통신사업단, 서울관광재단이 공개한 2026년 공고를 요약한 것입니다. 마감과 금액 표기는 공고에 실린 그대로 두었습니다.

## 한계

* 한국어 공고만 다루고, 사용자가 붙여넣은 텍스트만 읽습니다(PDF·HWP 파싱은 없습니다).
* 지역 매핑은 창업중앙대학 프로그램이 쓰는 다섯 권역만 덮습니다. 그 밖의 지역 표현은 `확인 필요`로 남습니다.
* 계획은 사람이 마감에서 거꾸로 센다는 전제로 만들어집니다. 발급 기관이 얼마나 걸리는지는 알지 못합니다.
